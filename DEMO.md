# DEMO: сценарий на 30 минут

## За день до
1. `pip install -e ".[dev]"`, затем проверь `py -3 -m pytest -q`, `py -3 -m ruff check .` и английский eval.
2. Windows: `$env:AGENT_CMD = "py -3 demo/fake_agent.py"; .\loop.ps1`. Linux/macOS:
   `AGENT_CMD='python3 demo/fake_agent.py' ./loop.sh`. Репетиция без API, 7 итераций.
   Сброс: `.\demo\reset.ps1` или `./demo/reset.sh`.
3. Перед показом проверь установленный Cursor Agent CLI:
   - `agent --version` и `agent status --format json`;
   - флаги CLI: `agent --help` (`-p`, `--force`, `--output-format`, `--trust`);
   - формат `.cursor/hooks.json` и поля ответа hook'а (`permission`, `user_message`, `agent_message`);
   - что `.cursor/rules/*.mdc` и `.cursor/commands/*.md` подхватываются в твоей версии.
4. Один настоящий прогон `./loop.sh`, запиши экран как резервное видео.

## Две ловушки (подготовленные, не случайные)
- **T1, скрытая причина.** Эмбеддер использует `hash()`, он рандомизируется между процессами.
  Тест в одном процессе проходит, а `index` в одном процессе плюс `search` в другом даёт мусор.
  Агент должен найти корень в другом модуле и добавить подзадачу T1.1. Срабатывает надёжно.
- **T2, морфология.** Одной правки регулярки на кириллицу мало: recall 0.79 при пороге 0.9
  (нужны ё→е, стоп-слова, стеммер). Сильный агент может сразу сделать всё и обойтись без
  перепланирования. Это нормально: скажи вслух, что harness проверяет итог в обоих случаях.

## Что показать в разборе
- Коммиты `iter N: T1 FAIL [replanned]`: перепланирование видно в истории.
- `🚫 protected path touched`: агент попытался подогнать `eval/`, harness откатил.
- Агент не ставит галочки сам: `plan.py done` вызывает loop после своей проверки.
- Живой агент может повести себя иначе, чем скрипт-репетиция. Это и есть смысл демо.

## Вопросы, которые зададут
- **Чем это лучше Agent mode в IDE?** Воспроизводимость, свежий контекст, проверки вне агента, лимиты, работа без человека.
- **Почему свежий контекст?** Длинная сессия деградирует и тащит ошибки; состояние в файлах можно ревьюить и откатывать.
- **Как агент не обманет проверки?** Acceptance-тесты и eval защищены, откат делает harness, галочки тоже.
- **Что если зациклится?** `MAX_FAILS` подряд без перепланирования → задача `[!]`, эскалация; общий `MAX_ITER`; `ITER_TIMEOUT`.
- **Стоимость?** Пока в `metrics.csv` только время; следующий шаг: токены/деньги за итерацию из логов CLI.
- **Что улучшить?** Параллельные worktrees для независимых задач, ревью-агент перед merge, метрики стоимости.

## Известные ограничения (скажи сам, раньше, чем спросят)
- Метрика recall считается на маленьком наборе (14 запросов): это демо метода, не бенчмарк.
- Стеммер примитивный, hashing-эмбеддер не семантический: «semantic» здесь условное название.
- `make check` не ловит всё: проверка корректности целиком зависит от качества тестов и eval.
